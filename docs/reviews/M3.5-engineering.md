## 1. 交付内容（S1–S6）

- **`apps/trading_daemon/`**：最小 SHADOW 运行入口（CLI `python -m apps.trading_daemon --mode synthetic-replay`）。
  先持久锁定预测（`PREDICTION_LOCKED` 哈希链条目）→ 后消费观察（`OBSERVATION_RECEIVED`）→ 一次性评分（`SCORED` 链条目即持久"已评分"记录）。
- **事件纪律**：event_id 幂等（同载荷重复=DUPLICATE；异载荷=CONFLICT+保守挂起）；逐源时序单调（乱序/晚回填=HELD）；未来时戳=HELD；TTL=EXPIRED；非法时钟/未准入来源/环境混用=REJECTED；全程审计入链。
- **重启/崩溃恰好一次**：真子进程 `os._exit` + 锁残留 + 租约接管审计；观察已入库评分前的崩溃由 `resume_pending_scores` 补分恰好一次（`recovered=true` 入链）。链重建是唯一状态源（`EVENT_CONSUMED` 条目）。
- **单写者**：租约锁（持锁拒绝；到期审计后接管）；双进程真竞争负例。
- **防尾截断/替换**：AuditLog 头部记录 + 外部锚 `journal-anchor.json`（mirror M3 账本锚模式）。
- **预注册**：`configs/forward_observation.yaml`（来源授权开关、B2 冻结 MA(2,4)、夹具数据集哈希、TTL、合成日历、S5 状态机）；纳入 daemon 代码身份。

## 6. 残余风险（如实）

1. **静态检查边界**：不拦计算性动态导入/exec（与 M1/M2 相同的已声明边界）。
2. **锚文件可信度** = 锚文件自身存储（单机 ADR-002 模型）；多机/防篡改存储属后续阶段。
3. **租约锁不检测持有进程存活**：持锁进程假死需等租约到期方可接管（保守设计，宁可停不可抢）。
4. **daemon 消费者单一**：当前仅官方 runner 与测试消费 daemon；S8 真实源接入前需重新评审事件契约与准入。
5. **Windows + Ubuntu 差异**：本地验证在 Windows；Linux 侧待远端 CI（`CI_REMOTE_PENDING`）确认，届时方可写 `REMOTE_VERIFIED`。
