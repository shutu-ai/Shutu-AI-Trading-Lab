## 设计要点（最小修复，不动旧协议）

1. **完成是收据链上的终态标记**：`WINDOW_COMPLETED` 记录即提交点。任何完成
   决策先 fail-closed 读链（新助手 `read_completion_records()`：链损坏即拒绝）。
2. **提交顺序 = 收据 → 快照**：收据未持久化 ⇒ 绝不写快照/evidence 副本；
   收据已提交而快照失败 ⇒ 可恢复的未完成态（exit 7）。快照经临时文件 +
   `os.replace` 原子落盘（POSIX 原子；Windows `MOVEFILE_REPLACE_EXISTING`；
   强制 LF；崩溃只留孤儿 `.tmp`，目标文件要么缺席要么完整）。
3. **幂等/终态语义**：同 facts 重跑 = 只修快照（不重复收据）；facts 漂移或
   换协议 = `REFUSED_ALREADY_COMPLETED`（零变更，含 journal）。
4. **status fail-closed**：共享校验 `_verify_completion_evidence()`——摘要 +
   协议 + **链绑定** + 重复/冲突 + 三链完整性；输出
   `completion_state`/`completion_problems[]`；退出码 0/6/7 可区分且文档化。
   可用性与完整性分离：exit 0 永远只是"命令完成且无完整性异常"，不是资格
   PASS；未开始/进行中查询保持 exit 0。
