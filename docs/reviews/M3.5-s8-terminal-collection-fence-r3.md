### P1-A 终态写入隔离（TERMINAL_FENCE=PASS）

旧行为（RED 实测）：已提交 `WINDOW_COMPLETED` 的窗口仍可经 `collect --once`
/ `--complete` 继续 `collect_once()` + 追加收据/会话（哨兵 feed 被调用、
journal 变更、exit 0）——完成窗口可经普通采集入口漂移。

修复：`cmd_collect` 在一切凭证读取、网络客户端、feed 访问与链写入**之前**
执行只读终态审查；封存窗口 → `TERMINAL_WINDOW_REFUSED` **exit 8**（新增，
契约表已更新），零磁盘写入；链损坏 → exit 6；合法未开始/进行中窗口路径
不变（guard 用例双向证明）。cycle 前二次复核缩小 TOCTOU 窗口；跨进程残余
风险如实记录（见下），不声称已消除。

### P1-B 纯离线恢复（OFFLINE_REPAIR=PASS）

新增 `repair-completion --state-dir <必填>`：不读凭证、不建网络客户端、
不采集、不新增收据/会话/事件（哨兵 + socket 密封证明）。资格门 = 恰一条
可验证已提交完成收据 + 快照缺失 + digest/协议/独立重算 eligibility 三重
匹配；成功 → 原子写快照（与完成路径同一字节形状）`REPAIRED_SNAPSHOT`
exit 0；已验证快照 → `ALREADY_COMPLETE_NOOP` 零字节；无完成 →
`NO_COMMITTED_COMPLETION`（绝不"帮忙完成"）；链损坏/跨协议/摘要漂移/
重复完成/篡改快照 → exit 6 拒绝（验证不过的证据永不被覆盖）；原子写失败
→ exit 7 可恢复且无假 COMPLETE。`collect --complete` 语义收窄为
"首次受控完成专用"；`operator-readiness.md` §D 按 T8 语义修订（最小修订
+ 修订说明）。

## 残余风险

1. **TOCTOU 跨进程窗口**：终态检查与 cycle 之间无单一跨进程锁（会话租约只
   保护 journal 会话，不覆盖收据追加与围栏本身）。入口 + cycle 前双重复核
   已把窗口缩到单 cycle 内部；单操作者主机一次一个 CLI 的操作纪律下风险
   极低，但未从机制上消除——已如实记录，未声称检查一次即原子。
2. **内部 API 面**：`run_collection_cycle` 本身未加硬围栏（测试/引擎内部面，
   T7 漂移拒绝测试依赖其构造拒绝状态）；唯一用户入口（CLI）已围栏。
   若未来新增第二采集入口，必须复用 `_terminal_gate`。
3. `repair-completion` 与 exit 8 为新对外契约：自动化不得再假设
   "collect 对任何状态都会尝试采集"。已文档化于 runner docstring 与
   `operator-readiness.md` §D。
4. **T8_CI=REMOTE_PENDING**：Linux 矩阵待未来授权推送后的双平台 CI。
5. RED 期间旧代码向 r1 写入过一个未跟踪模拟 evidence 文件（已删除恢复
   原状；GREEN 围栏结构性防复发；详见 `r3/red-green.md` 附注）。
