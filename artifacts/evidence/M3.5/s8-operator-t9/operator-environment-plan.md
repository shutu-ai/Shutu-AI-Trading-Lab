# 独立运行环境与网络出口隔离方案（operator-environment-plan — T9.2，LOCAL_ONLY 文档）

> 本文件是**操作者未来在其受控主机亲自执行**的方案说明；本轮未操作任何网络、
> 防火墙、代理、DNS、系统设置或证书存储。未按本方案完成验证前，
> `HOST_EGRESS_ISOLATION_UNVERIFIED` 保持不变。

## 1. 目标边界（一句话）

一个临时、独占、无 Broker 下单能力的采集环境：**仅**允许到
`data.alpaca.markets:443` 的预注册 HTTPS GET（路径白名单由预注册
`transport.allowed_paths` 限定）；**拒绝** `api.alpaca.markets`、
`paper-api.alpaca.markets` 与一切其他互联网目的地——在网络层拒绝，
而不是靠应用层。

## 2. 边界图（逻辑）

```text
┌────────────────────────────────────────────────────────────┐
│ 受控采集环境（专用 VM / 容器 / 受控代理后面的专用主机）        │
│                                                            │
│  采集子进程（python scripts/run_m35_s8_shadow_real.py）     │
│   ├─ 应用层守卫 GuardedGetClient（GET-only + host/path 白名单│
│   │   + 禁重定向 + 超时）——必要但不充分                      │
│   └─ 出口 → 本环境内唯一放行：data.alpaca.markets:443        │
│              （HTTPS GET，预注册路径）                       │
│                                                            │
│  网络层策略（default deny）：                               │
│   ├─ 允许：data.alpaca.markets:443（解析结果 + SNI 校验）    │
│   ├─ 拒绝：api.alpaca.markets、paper-api.alpaca.markets     │
│   ├─ 拒绝：一切其他 IPv4/IPv6 目的地与端口                  │
│   └─ DNS：仅解析白名单域（或解析也被 ACL 约束）——防泄漏      │
└────────────────────────────────────────────────────────────┘
          │ （唯一出口，经显式代理时代理自身必须同 ACL）
          ▼
        互联网
```

## 3. 为什么应用层守卫 ≠ 主机隔离（必须双层的理由）

`GuardedGetClient` 在**采集进程内**强制 GET-only、host/path 白名单、
禁重定向。它不能防：

- 同环境内**其他进程**任意出网（采集器被替换、被注入、或旁边跑了别的东西）；
- 采集器自身的供应链缺陷（应用层守卫被绕过的代码路径）；
- 凭证被读取后经**别的通道**外传（DNS、非常规端口）。

因此网络层 default-deny 是独立必要条件；两层证据缺一不可。

## 4. DNS / 地址族 / 代理的具体陷阱（逐项）

| 项 | 陷阱 | 要求 |
|---|---|---|
| 动态域名 L3 放行 | "按域名放行"的防火墙规则实际依赖解析时点的 IP 集合；Alpaca 数据端点 IP 会轮换，快照式放行会**静默失效或放错** | 用支持 FQDN 动态解析的策略引擎（容器/代理层），或在每次会话前解析并将**当日解析结果**写入 ACL，负例中验证拒绝面 |
| DNS A 与 AAAA | 只放行 A 记录、IPv6 仍可直连绕过；或 DNS 查询本身走了未受控通道 | 同时封 v4/v6；DNS 服务器固定为受控解析器；负例必须覆盖 `AAAA` 路径 |
| IPv6 泄漏 | Windows/容器默认可能优先 v6；放行面若只写 v4，v6 全通 | 显式禁用或显式 ACL v6；负例实测 v6 目的地被拒 |
| TLS/SNI | IP 层放行后，同 IP 托管的其他域名（含交易 API 若共址）可能被顺带放行 | 在代理/策略层校验 SNI=白名单域；或确认目标 IP 不与禁行域共址（无法确认时按"可能共址"处理） |
| 显式 HTTP(S)_PROXY | 进程读了代理环境变量就会把**全部**流量交给代理——主机层防火墙规则对代理隧道内的目的地**不可见**；看似生效的 Windows 防火墙规则不覆盖 CONNECT 隧道 | 采集会话内**显式固定**代理变量（或显式置空）；代理自身实施同一 default-deny ACL；负例必须经代理路径实测 |
| Windows 系统代理（WinINET/WinHTTP） | 与环境变量是两套；urllib 走系统代理时规则同上 | 检查 `netsh winhttp show proxy` 与用户系统代理设置；会话内固定，不留"自动检测" |
| HTTP CONNECT | CONNECT 可达任意 host:port——代理若不限目标，等于无隔离 | 代理 ACL 限制 CONNECT 目标到白名单域:443 |
| 代理机自身外连 | 代理成了新的"全通出口" | 代理宿主执行同一 default-deny；其自身更新/遥测通道单独列明或关闭 |
| DNS 泄漏 | 应用层白名单不约束 DNS；DNS 经代理时目标解析在代理侧 | 固定 DNS、记录解析行为；负例含一个不存在于白名单的域名的解析+连接尝试（应失败） |
| 重定向 | 应用层已禁（`redirects: forbidden`）；网络层不需要补，但负例可验证 3xx 不被跟随 | 保持应用层配置不变 |

**不可假设**：Windows 上某条"看起来生效"的规则自动覆盖代理隧道、IPv6、
或采集器子进程。每一条都必须用 §7 的负例矩阵实测。

## 5. 推荐实现（按优先级；适用条件与未知项如实列出）

**方案 A（推荐）：一次性专用 VM / WSL2+容器，采集完即弃**
- 适用：操作者有一台可开 Hyper-V/虚拟化的 Windows 或任意宿主。
- 做法：干净 VM（或容器网络 namespace）内仅运行采集器；VM 网卡出口在
  宿主虚拟交换机/容器策略上 default-deny，仅放行 `data.alpaca.markets:443`
  （FQDN 策略或会话内解析结果）；DNS 固定；不装其他软件。
- 优点：与日常主机完全隔离，"临时、独占"语义最干净；会话结束销毁。
- **2026-11-22 T9.7 修订（重要）**：方案 A 的"销毁"仅指**计算资源**；真实
  窗口需 ≥5 全覆盖交易日的 receipt/journal 链**跨日持续存在**——必须配合
  持久状态卷（独占/权限最小化/加密/跨日字节不覆盖/备份摘要/重建绑定），
  详见 `../s8-operator-t9-7/operator-gate-reconciliation.md` §6。单日即弃
  的纯无状态用法只适用于模拟/自测，不适用于真实窗口。
- 未知项：宿主虚拟化网络（NAT/桥接）下 ACL 生效点需实测；WFP/FQDN 工具
  的选择与许可证由操作者决定（本仓库不指定品牌、不代装）。

**方案 B（推荐备选）：受控正向代理（default deny + 域:端口 ACL）**
- 适用：操作者已有或愿意起一个小代理（如 squid/envoy 类），其 ACL 支持
  CONNECT 目标白名单。
- 做法：采集环境的唯一出口指向该代理；代理仅允许
  `CONNECT data.alpaca.markets:443`（校验 SNI 由 TLS 层自然产生）；代理宿主
  自身入/出站同样 default-deny（仅管理通道）。
- 优点：FQDN 层控制天然正确（代理见 SNI/Host）；与方案 A 可叠加。
- 未知项：代理软件选型/加固/日志保留策略由操作者负责；本仓库不代选代装。

**方案 C（不推荐，仅在 A/B 均不可行时的降级）：日常主机临时主机防火墙**
- 明确风险：与办公/家庭其他流量共存；规则遗漏面大（v6/代理/子进程）；
  违反"临时独占"目标。若必须使用：default-deny 出站 + 白名单放行 +
  §7 全矩阵负例全部通过，并把"共享主机"如实写入 attestation 的已知风险。
- 本轮与未来采集均**不由 Codex 修改**任何防火墙/代理/DNS/路由/证书设置。

**统一约束**：不购买付费数据、不开 Paper 写、不装 broker CLI/SDK 到采集环境；
采集环境内只存在本仓库检出的代码 + Python 运行时。

## 6. 子进程边界证明 + 单一已验证环境

- **子进程同边界**：隔离策略作用于环境（VM/容器/代理），进程树自然继承；
  证明方式 = 负例从**采集器同型子进程**发起
  （`python -c "import urllib.request,sys; ..."` 形态，见
  `operator-preflight-pack.md` §C 模板），而非仅交互 shell；工作目录用
  仓库检出，但不给它超出预注册的任何配置。
- **单一已验证环境**：办公代理环境与家庭直连**不要求都通过**——选择
  **一个**完成 §7 全矩阵负例的环境作为未来观察窗口的唯一目标环境；
  记录其环境标识（主机类型/网络类型/代理与否，非敏感）。
  **切换环境 = 全矩阵重验**，不得沿用上一次结论。

## 7. 可证伪的准入条件（全部满足才可把 C 项标 VERIFIED_BY_OPERATOR）

F-1 允许域应用层可达：`data.alpaca.markets:443` HTTPS GET（无凭证）收到
    **任意** HTTP 响应（401/403/4xx 均可——证明链路通，不强求精确 401）。
F-2 两个交易域在**网络层**失败（连接超时/拒绝/DNS 失败——**不是** HTTP
    401/403，即请求根本没到达对端应用）。
F-3 非白名单域（任选 2 个公网站点）网络层失败。
F-4 IPv6 目的地同样被拒（禁用或 ACL 证据 + 实测）。
F-5 直连与显式代理/CONNECT 两条路径**分别**实测（用哪个环境就测哪条）。
F-6 采集器同型**子进程**内重跑 F-1～F-4 结果一致。
F-7 DNS 路径受控（固定解析器；白名单外域名解析+连接失败的证据）。
F-8 全部证据为操作者本地留档（命令+时间戳+输出摘要），签名入
    attestation（仓库内只有空白模板）。

任何一条无法证明 → 该项如实记 `BLOCKED` 或 `UNVERIFIED`，
`HOST_EGRESS_ISOLATION_UNVERIFIED` 保持；不得为凑成功放宽 allowlist。

## 8. 运行期并发纪律（TOCTOU 的操作面缓解）

事实（T8 已记录）：终态围栏在入口与 cycle 前各做一次只读复核，但
**不存在覆盖 read-check-write 全流程的跨进程互斥**（`SessionLock` 只保护
journal 会话）。因此运行规程：

1. **单操作者 / 单实例 / 固定独立 state dir**（建议每次观察窗口一个新建的
   专用目录路径，避免与任何旧目录混用）；
2. 观察窗口内**禁止并发运行第二个 CLI**（包括第二个 `collect`、`status`
   也只允许在采集命令完全退出后运行）；
3. 异常停止规则：采集命令未按预期退出（挂起>poll_timeout+30s）→ 终止该
   进程树，**不再发起第二个采集**，改跑 `status` 与 `repair-completion`
   诊断（均只读或纯本地），如实记录退出码与状态；
4. 每次窗口只允许**一个** `collect --once`（由未来的单独授权界定）；
5. 状态目录路径、环境标识记录在 attestation（非敏感 hash 即可）。

## 9. 风险项汇总

| # | 风险 | 处置 |
|---|---|---|
| R1 | FQDN-ACL 因 IP 轮换静默失效 | 会话前解析+当日 ACL；F-1 失败即停 |
| R2 | 代理隧道绕过主机防火墙 | 代理自身 ACL + F-5 双路径实测 |
| R3 | IPv6 旁路 | 显式禁用/ACL + F-4 |
| R4 | 代理机成为全通出口 | 代理宿主 default-deny + 独立审计 |
| R5 | 子进程边界不同 | F-6 同型子进程重测 |
| R6 | 并发 CLI 造成跨进程写交错 | §8 操作纪律 + T8 已记录的机制残余 |
| R7 | 采集环境内凭证残留 | 会话结束销毁环境/清进程树；凭证仅存在于采集子进程环境（§B 方案） |
| R8 | 方案 C 共享主机固有暴露 | 如实标注于 attestation；优先 A/B |
